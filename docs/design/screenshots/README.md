# Скриншоты сайта (визуальный референс)

Эти изображения — визуальный референс для построения дизайн-документации. Они используются нейросетью на этапе 2 (см. `docs/design/`) для подтверждения дизайн-токенов, извлечённых из CSS.

**Важно:** на этих скриншотах есть несколько технических артефактов скриншот-инструмента, которые **не являются реальным дизайном**. Читай этот файл перед интерпретацией изображений.

## Артефакты скриншотов (НЕ интерпретировать как дизайн)

### Фиксированные фоновые изображения

На некоторых страницах в фоне используется размытое декоративное изображение калькулятора. В CSS это реализовано через `background-attachment: fixed` (или подобную технику) — то есть фон **не скроллится вместе с контентом**, остаётся на месте при прокрутке страницы.

Скриншот-инструмент **не умеет корректно захватывать** фиксированные фоны при сохранении полной длины страницы. В результате:

- На верхней части скриншота фоновая картинка отображается.
- На остальной (большей) части страницы фон отсутствует — выглядит как пустой / прозрачный.

**Реальное поведение в браузере:** фон с размытым калькулятором виден на всей высоте экрана, всегда. При скролле текст и блоки прокручиваются, фон остаётся на месте.

**Где это есть:**

- `calculator-desktop.png` и `calculator-mobile.png` — вся страница калькулятора.
- `order_conf-desktop.png` и `order_conf-mobile.png` — вся страница подтверждения заказа.
- `main-desktop.png` и `main-mobile(*)` — блок «Калькулятор стоимости» на главной (визуально это секция с заголовком, отсылающая на страницу калькулятора).

При построении дизайн-документации **указать, что у этих блоков есть фиксированное фоновое изображение** (с размытием и подсветкой), даже если на скриншоте оно не видно после верхней области.

### Разделение мобильной главной на два файла

Мобильная главная не уместилась в один скриншот из-за ограничений инструмента на максимальную высоту. Файлы `main-mobile(1).png` и `main-mobile(2).png` нужно читать **как одну непрерывную страницу**:

- `(1)` — верхняя половина (от шапки до примерно середины контента).
- `(2)` — нижняя половина (продолжение, до футера).

Между ними нет пропуска контента — они логически склеиваются.

Для десктопа разделение не понадобилось — `main-desktop.png` содержит всю главную одним файлом.

## Эталон масштаба

Эти скриншоты сделаны с локальной версии сайта в `public/` (то есть с того кода, который сейчас живёт в проекте), а **не с tilda_export**. Это важно: в `tilda_export/` интерфейс местами завышен по масштабу, тогда как в `public/index.html` — пропорции «правильные». При построении дизайн-системы за эталон масштаба берём именно `public/`.

## Что НЕ нужно делать с этой папкой

- Не редактировать сами PNG.
- Не использовать эти скриншоты как content на сайте.
- Не пытаться «дорисовать» отсутствующий фон в файлах с артефактами — он реально есть в браузере, просто инструмент его не захватил.

## После завершения дизайн-документации

Эта папка остаётся в проекте как исторический референс. Когда `docs/design/` будет наполнен, скриншоты — это «исходник», по которому он построен. Удалять не нужно.
