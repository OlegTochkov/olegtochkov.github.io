# Анти-правила, извлечённые из видео-разборов веб-дизайна

Документ — переработанная выжимка из трёх видео про ошибки в веб-дизайне и маркетинговое мышление в интерфейсе. Каждый пункт сформулирован как **анти-правило** («чего НЕ делать») с короткой причиной. Это база для финального документа `docs/design/do-and-dont.md`.

Материал переформулирован своими словами; дословные транскрипты не воспроизводятся.

## Видео 1 — Семь ошибок, выдающих новичка

### Анти-правило 1.1. Избыточная анимация

- **Не делать:** анимировать каждый блок (вылеты слева, справа, сверху, снизу) ради «оживления» сайта.
- **Почему плохо:** анимация, придуманная на финальном этапе ради «дороговизны», работает наоборот — выдаёт безвкусие. Хороший пользователь сделает то же самое за 5 секунд через DevTools — значит, ценности такие эффекты не несут.
- **Когда уместна анимация:** если она заложена в концепции с самого начала (например, заголовок при скролле превращается в логотип; блок фиксируется и даёт смысловой акцент). Не «вылет элементов», а интегральная часть идеи.
- **Применимость к нашему проекту:** мы — статичный сайт без вау-эффектов. Анимации только функциональные: hover-состояния кнопок, плавный скролл к якорю, открытие мобильного меню. Никаких декоративных вылетов.

### Анти-правило 1.2. Перегруженность визуала и отсутствие иерархии

- **Не делать:** дублировать декоративные элементы (обводки, акценты) из блока в блок. Когда «всё акцент» — ничего не акцент.
- **Почему плохо:** новички считают, что пустое пространство = слабый дизайн. На деле — пустое пространство ведёт пользователя к нужному действию.
- **Анти-применение:** уменьшать количество визуального шума, доверять воздуху, делать акценты только на важном (имя, опыт, ключевые цифры, CTA).

### Анти-правило 1.3. Отсутствие системы отступов

- **Не делать:** межблоковые отступы «на глаз» — 100px в одном месте, 111px в другом, 10px между заголовком и текстом в одной секции, 20px в другой.
- **Почему плохо:** разрозненные отступы превращают страницу в визуальную кашу. Пользователь не считывает смысловые группы.
- **Анти-применение:** одна сетка отступов на весь сайт. Например, шкала 8 / 16 / 24 / 32 / 64 / 96 / 128 пикселей. Любой отступ берётся только из этой шкалы.

### Анти-правило 1.4. Разное скругление углов

- **Не делать:** в одном блоке кнопка со скруглением 8px, в соседнем 12px, в карточке 20px без какой-либо системы.
- **Почему плохо:** мелкие несогласованности (15–20 на странице) дают общее ощущение «дешёво».
- **Анти-применение:** определить набор скруглений (например: мелкие элементы 4px, кнопки и инпуты 8px, карточки 16px, аватары — круг), и больше никаких значений нигде не использовать.

### Анти-правило 1.5. Иконки в разных стилях

- **Не делать:** смешивать иконки из разных наборов (заливка + контур, разные толщины линий, разные углы скругления).
- **Почему плохо:** даже при хорошей композиции это создаёт ощущение «собрано из лоскутов».
- **Анти-применение:** использовать ровно один свободный icon pack (Lucide, Heroicons, Feather — все MIT). Никаких смешиваний.

### Анти-правило 1.6. Интерфейс не даёт обратной связи

- **Не делать:** оставлять интерактивные элементы без визуальной реакции; делать страницы 404, которые не помогают пользователю; не показывать подтверждение после отправки формы.
- **Почему плохо:** пользователь не уверен, что действие принято, либо вообще не понимает, на что можно нажать.
- **Анти-применение:** у каждой кнопки — hover-состояние, у каждой формы — подтверждение, у 404-страницы — нормальная навигация обратно. Это закладываем сразу.

### Анти-правило 1.7. Текст ради текста

- **Не делать:** писать длинные абзацы там, где должна быть короткая суть.
- **Почему плохо:** пользователь не читает — сканирует. Длинный текст превращается в «фон», на котором теряется главное.
- **Анти-применение:** в каждом блоке — минимум слов, максимум смысла. Тарифы — список из 5 пунктов вместо абзацев. Карточки услуг — заголовок + 1–2 строки + цена.

## Видео 2 — Пять типичных ошибок

### Анти-правило 2.1. Гигантизм элементов

- **Не делать:** ставить размеры шрифтов «как кажется на отдалённом макете в Figma». Текст 36px для описания, который смотрится нормально с отдаления, на реальном мониторе превращается в «версию для слабовидящих».
- **Анти-применение:** все размеры проверять в реальном масштабе экрана (1:1). На десктопе body-текст — обычно 16–18px, описание — 14–18px, заголовки — 24–48px (зависит от уровня). Никаких body 36px.
- **Связь с нашим проектом:** в `tilda_export/` масштаб местами завышен. Эталон масштаба — `public/index.html`.

### Анти-правило 2.2. Работа без сетки

- **Не делать:** размещать элементы свободно, без привязки к колонкам.
- **Почему плохо:** на разных экранах вёрстка ломается, элементы вылезают за пределы или скучиваются.
- **Анти-применение:** базовая ширина контента — около 1200px. Внутренняя сетка — 12 колонок (стандарт). Все важные блоки начинаются и заканчиваются на колонках, а не «где попало».

### Анти-правило 2.3. Неправильная система группировок

- **Не делать:** одинаковые отступы между «всем подряд», независимо от логики (внутри карточки и между карточками — один и тот же отступ).
- **Почему плохо:** пользователь не понимает, какие элементы относятся к одной смысловой группе.
- **Анти-применение:** правило кратности. Внутренние отступы внутри элемента = X. Отступы между связанными элементами = 2X. Отступы между смысловыми блоками = 4X. Сразу видно структуру.

### Анти-правило 2.4. Нарушение ритма сайта

- **Не делать:** в одном блоке H2 = 50px, в другом 72px, в третьем 38px; в одном месте отступ от заголовка до текста = 20px, в другом = 12px.
- **Почему плохо:** ломается ощущение единой системы, сайт распадается на отдельные «куски».
- **Анти-применение:** один раз решили — H2 = 36px, отступ под H2 = 24px — и так везде до конца проекта.

### Анти-правило 2.5. Непонимание целевого действия

- **Не делать:** прятать CTA-кнопку под массой декора, делать её того же размера и цвета, что и остальной текст, требовать скролла, чтобы её найти.
- **Почему плохо:** клиент уходит не потому, что не захотел, а потому, что не нашёл, где нажать.
- **Анти-применение:** на первом экране — одна заметная CTA-кнопка контрастного цвета. Текст рядом — короткий: 15 лет опыта, 100 сотрудников, 15 000 довольных клиентов. Главное — в крупном, лаконичном виде.

## Видео 3 — Маркетинговое мышление в интерфейсе

Это видео — про дизайн через призму маркетинга. Несколько универсальных принципов, релевантных для нашего проекта.

### Принцип 3.1. Один экран — одна главная мысль

- **Не делать:** на первом экране — две CTA одинакового веса, четыре призыва, шесть разнонаправленных предложений.
- **Почему плохо:** когда выбор слишком велик — выбора нет вообще; пользователь рассеивается.
- **Анти-применение:** на каждой странице — один главный CTA. Если другие действия есть, они визуально слабее: меньше, прозрачнее, без акцентного цвета.

### Принцип 3.2. Маркетинг = снижение когнитивного трения

- **Не делать:** заставлять пользователя «думать», «расшифровывать», «интерпретировать». Аббревиатуры, неочевидные обозначения, размеры в загадочных единицах (S / M / L без пояснения).
- **Анти-применение:** все ключевые величины — в понятных единицах. Цены — в BYN. Размеры — конкретные (например, для уборки — м²). Сроки — в часах / днях.

### Принцип 3.3. Позиционирование считывается за 3–5 секунд

- **Не делать:** размытые лозунги вроде «новый уровень бизнеса», «качество и надёжность» — фразы, которые подходят к любой компании.
- **Анти-применение:** оффер за 3 секунды должен ответить на вопросы: куда я попал, что мне предлагают, для кого это, что делать дальше.
- **Анти-критерий:** если фраза-оффер подходит к любому сайту в индустрии — это плохой оффер.

### Принцип 3.4. Визуал — это сигнал доверия

- **Не делать:** ставить стоковые фотографии «деловых людей в офисе», использовать сгенерированные нейросетью обложки в космической стилистике.
- **Анти-применение:** для клининга — реальные фотографии бригады, помещений до/после, рабочего процесса. Доверие строится на конкретике.

### Принцип 3.5. Консистентность создаёт ощущение бренда

- **Не делать:** на одной странице кнопки одной формы, на другой — другой; на одной — синие, на другой — голубые; на одной — с тенью, на другой — плоские.
- **Анти-применение:** одна кнопка primary на весь сайт. Одна secondary. Одна форма поля ввода. Одни иконки. Одни отступы.

### Принцип 3.6. Хороший дизайн — это удаление

- **Не делать:** «украшать» интерфейс. Добавлять декор «чтобы не было пустоты». Заполнять каждый угол.
- **Анти-применение:** при любом ощущении «здесь чего-то не хватает» сначала пробуем убрать соседние элементы, а не добавить новые. Воздух — главный союзник.

### Принцип 3.7. Управление вниманием через контраст

- **Не делать:** делать важное и второстепенное одинаковыми по размеру / контрасту.
- **Анти-применение:** автор товара — тоньше и тише, чем сам товар. Подписи — мельче основного. Главное всегда крупнее, ярче, окружено воздухом.

### Принцип 3.8. Группировка по Gestalt

- **Не делать:** разносить связанные элементы (заголовок и его описание) на разные расстояния.
- **Анти-применение:** внутри одной смысловой группы — отступы минимальны, между группами — максимальны. Это закон близости — мозг автоматически считывает «что с чем».

### Принцип 3.9. Динамика через композицию

- **Не делать:** ставить все элементы строго по центру, перпендикулярно, симметрично — это даёт «мёртвый» статичный дизайн.
- **Анти-применение:** разворачивать объекты, выводить детали за границы карточек, делать акцент через смещение из центра — это создаёт «живость» без анимации.

### Принцип 3.10. Боязнь «грязи»

- **Не делать:** перегружать сайт. Конфликт цветов, конфликт форм, слишком много акцентов, отсутствие системы.
- **Анти-критерий:** если в первые 2 секунды восприятие даёт ощущение «тяжело» — что-то лишнее.

### Принцип 3.11. Работа через референсы, а не озарения

- **Не делать:** «изобретать с нуля» в каждом блоке.
- **Анти-применение:** есть библиотека «нормально решённых блоков» — берём оттуда, адаптируем. Не «гениальная идея», а проверенный паттерн.

### Принцип 3.12. Мыслить экраном, а не элементом

- **Не делать:** доводить отдельный блок до идеала, не глядя на страницу целиком.
- **Анти-применение:** регулярно отдалять и смотреть страницу с расстояния — есть ли ритм, баланс, ясная иерархия.

## Сводный «дух» всех трёх видео

Если свести всё к одному предложению:

**Хороший дизайн — это удаление лишнего, выстраивание единой системы и фокус на одном действии пользователя. Плохой дизайн — это украшения без системы, перегруженность и потеря фокуса.**

Это и есть наш главный анти-критерий: на каждом шаге задавать вопрос «работает ли это на одно главное действие пользователя, или мешает?»
