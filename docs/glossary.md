# Словарик технических терминов

Краткие объяснения терминов, которые встречаются в документации и в работе с проектом. Пишется простым языком — для маркетолога, осваивающего разработку.

Если в каком-то документе встретился непонятный термин, которого здесь нет — это сигнал расширить словарик.

## Базовые концепции

**Frontend (фронтенд)** — клиентская часть сайта. То, что выполняется в браузере пользователя: HTML, CSS, JavaScript. Это то, что человек видит и с чем взаимодействует.

**Backend (бэкенд)** — серверная часть. То, что выполняется на сервере и не видно пользователю напрямую. Обрабатывает запросы, общается с базой данных, отправляет письма и т.д.

**Static site (статический сайт)** — сайт из готовых HTML-файлов, которые сервер просто отдаёт браузеру. Быстро, дёшево, надёжно. Наш текущий этап.

**Dynamic site (динамический сайт)** — сайт, где содержимое страниц генерируется на сервере по запросу. Нужно для личных кабинетов, чатов, корзин. Наш будущий этап.

**Rendering (рендеринг)** — процесс превращения кода в то, что видит пользователь.

## Инструменты разработки

**Git** — система контроля версий. Локальная "машина времени" для файлов проекта. Каждое сохранение (`commit`) можно потом откатить.

**Repository (репозиторий)** — папка проекта, отслеживаемая Git.

**Commit (коммит)** — снимок состояния файлов в Git с пометкой "что я тут сделал".

**Branch (ветка)** — параллельная линия истории в Git. Можно ветвиться, экспериментировать, потом сливать или удалять. Главная ветка обычно `main`.

**Diff (дифф)** — отображение разницы между двумя состояниями файлов. "Было / стало".

**GitHub** — онлайн-сервис для хранения Git-репозиториев. В нашем проекте пока **не используем**.

**Node.js** — программа, позволяющая запускать JavaScript на компьютере (а не только в браузере). Нужна для всех современных инструментов веб-разработки.

**npm** (Node Package Manager) — менеджер пакетов для Node.js. Что-то вроде App Store для разработчика: устанавливаешь библиотеки одной командой `npm install <имя>`.

**npx** — команда из комплекта npm. Запускает программу из пакета без полной установки. Удобно для разовых запусков.

**Package (пакет)** — отдельная библиотека или инструмент, опубликованная в npm.

**Dependency (зависимость)** — пакет, от которого зависит твой проект. Список зависимостей лежит в `package.json`.

## Astro

**Astro** — наш фреймворк. Инструмент для разработки, позволяющий писать сайт компонентами, а на выходе получать обычные HTML-файлы.

**Component (компонент)** — переиспользуемый кусок интерфейса. Например, шапка сайта может быть компонентом `Header.astro`, который вставляется на все страницы одной строкой `<Header />`.

**Layout (макет)** — компонент, описывающий общую структуру страницы (шапка, основная часть, футер). Конкретные страницы оборачиваются в макет.

**Build (сборка)** — процесс, при котором Astro берёт твои компоненты и собирает из них готовые HTML-файлы. Запускается командой `npm run build`.

**Dev server (дев-сервер)** — локальный сервер для разработки. Запускается командой `npm run dev`. Открывается в браузере по адресу типа `http://localhost:4321`. При изменении файлов страница автоматически перезагружается.

**SSG** (Static Site Generation) — генерация статических HTML-файлов. Наш режим на первом этапе.

**SSR** (Server-Side Rendering) — рендеринг страниц на сервере на лету. Нужен для динамики (личный кабинет). Astro умеет и так, и так.

## Cursor

**Rule (правило)** — текстовый файл в `.cursor/rules/`, который нейросеть читает каждый раз перед ответом. Туда кладут постоянные инструкции ("отвечай по-русски", "не используй GPL").

**Skill (навык)** — папка с инструкцией для конкретного типа задач. Нейросеть читает её, только если задача подходит под описание. У нас пока нет, появятся при необходимости.

**Hook (хук)** — скрипт, автоматически запускающийся при событиях (например, перед коммитом — проверить, что нет упоминаний Тильды).

**Subagent (субагент)** — отдельная "копия" нейросети с узкой ролью. У нас есть `bug-hunter` — проверяет проект и не правит файлы.

**MCP** (Model Context Protocol) — стандарт, позволяющий подключить нейросеть к внешним сервисам (Google Search Console, Яндекс.Метрика, базы данных).

**Plan mode** — режим Cursor, где сначала составляется план, и только потом он выполняется по утверждению.

**Agent mode** — режим, в котором нейросеть может править файлы и выполнять команды.

**Ask mode** — режим только для общения. Нейросеть отвечает на вопросы, ничего не меняет.

**Max Mode** — режим с увеличенным контекстом и максимальным размышлением. Дорогой, для самых сложных задач (миграция главной, калькулятор).

**Thinking effort** — настройка "сколько модель размышляет перед ответом". Чем выше — тем точнее ответ, тем больше расход токенов.

## Лицензии

**Permissive license (разрешительная лицензия)** — лицензия, позволяющая использовать код в любых целях, включая коммерческие, без обязательств открывать свой код. Это MIT, Apache 2.0, BSD, ISC, MPL 2.0. **Разрешены в нашем проекте.**

**Copyleft license (копилефт)** — лицензия, требующая, чтобы любой код, использующий её, тоже был открыт под той же лицензией. Это GPL, AGPL, LGPL. **Запрещены в нашем проекте.**

**OFL** (SIL Open Font License) — стандартная свободная лицензия для шрифтов. Под ней живут почти все Google Fonts. Разрешена.

**CC0 / CC-BY** — Creative Commons лицензии для контента (картинки, тексты). CC0 — полностью свободно, CC-BY — нужно указывать автора.

## Веб и SEO

**SEO** (Search Engine Optimization) — оптимизация сайта для поисковиков (Google, Yandex). Влияет на позицию в выдаче.

**Sitemap** — XML-файл со списком всех страниц сайта. Поисковики используют его для индексации.

**Robots.txt** — текстовый файл, говорящий поисковикам, что можно и что нельзя индексировать.

**OG-теги** (Open Graph) — метатеги для красивого превью при репостах в соцсетях.

**Canonical URL** — указание поисковикам, какой адрес страницы считать "главным" (на случай дубликатов).

**Schema.org / структурированные данные** — формат разметки, которую понимают поисковики, чтобы лучше показывать сайт (LocalBusiness, Service, FAQ).

## Прочее

**Lint / Linter (линтер)** — проверка кода на типичные ошибки. Например, ESLint для JavaScript, Stylelint для CSS.

**Telegram-бот** — программа, общающаяся через Telegram API. В нашем случае будет принимать заявки с сайта и пересылать менеджеру.

**API** (Application Programming Interface) — способ, которым программы общаются между собой. Например, у Telegram есть Bot API — через него можно отправлять сообщения программно.

**Endpoint** — конкретный адрес в API, обрабатывающий определённый запрос. Например, `/api/lead` — endpoint для отправки заявки.

**localStorage** — хранилище в браузере пользователя, переживающее перезагрузку страницы. Не отправляется на сервер. Понадобится для сохранения прогресса в калькуляторе.

**Cookies (куки)** — небольшие данные, сохраняемые сайтом в браузере пользователя. Используются для идентификации повторных визитов и аналитики.

**DNS** (Domain Name System) — система, переводящая доменные имена (`cleanlogic.by`) в IP-адреса серверов. Переключение DNS = смена того, какой сервер открывается по нашему домену.

**Staging** — копия сайта на отдельном адресе для тестирования перед публикацией.

**Production / прод** — рабочая, "боевая" версия сайта, которую видят настоящие посетители.

**Hot reload / Live reload** — функция дев-сервера: при изменении файла страница автоматически обновляется в браузере.
